# Telcom-Contact-Center-DWH-SQL-project
This is an end to end Telcom contact center Datawarehouse SQL project 
This project is based on medallion architecture including 3 schemas: Bronze, Silver, Gold
Bronze: Raw data is ingested directly to bronze layer without making any changes to preserve the raw data
Silver: Raw data is now cleaned and transformed and then loaded to Silver layer
Gold: Business ready data including business logics, includes additional calendar table as well

Created Stored procedures: 
  bronze.load_bronze to automatically truncate and load new data into bronze tables
  silver.load_silver to automatically truncate and load new data into silver tables
  gold.load_gold to automatically truncate and load new data into gold tables
  
DATA sets: Generated by Chat GPT
contains 4 CSV files for Calls, customers, call reasons and employees
NOTE: If you want to run the script, then download the datasets and change the file path in bronze load 
'FROM 'D:\call_center_source_data\.csv'' to the donwloaded path

Assumption:
We get a new updated CSV file daily or weekly or monthly, so automation can completely truncate and load new data

CALL CENTER SOURCE DATASET
Domain: Telecom Customer Support
Period: 2025-07-01 to 2026-06-30

Grain:
- One row in calls files = one customer interaction.
- Every call has a case_id.
- Multiple calls may belong to the same case.
- Abandoned calls have no employee assignment.
- Missed calls DO have an employee_id because the interaction was assigned to an agent who did not answer.

Business rules:
- call_status: Answered / Abandoned / Missed
- resolution_status: Resolved / Unresolved
- FCR = 1 only when the case is resolved on its first and only interaction; otherwise 0.
- Missing CSAT/NPS means no survey response and must not become zero.
- CSAT valid range: 1-5
- NPS valid range: 0-10

Intentional data-quality issues:
- trailing spaces
- inconsistent sentiment capitalization
- invalid CSAT/NPS values
- invalid employee/customer IDs
- duplicate call rows
